## 1. 项目概述

**职业罗盘（CareerCompass）** 是一个面向求职者和招聘方的综合职业管理平台，基于 React + Vite 构建，使用 IndexedDB 作为本地数据库。

### 技术栈

| 技术 | 用途 |
|------|------|
| React 18 | UI 框架 |
| Vite 8 | 构建工具 |
| React Router 7 | 路由管理 |
| IndexedDB | 本地数据库（浏览器端） |
| localStorage | 用户偏好、记住密码、主题存储 |
| CSS 变量 | 深浅主题切换 |

## 2. 快速开始

### 从 GitHub 克隆后首次运行

```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器
npm run dev

# 3. 生产构建
npm run build
```

首次打开页面后，系统会自动：
- 在 IndexedDB 中创建数据库表（stores）
- 填充示例数据（8个职位机会、5条申请记录、4个收藏、5条消息、5条系统日志）
- 在 `localStorage` 写入 `db_seeded_v4` 标记，以后不再重复填充

### 浏览器兼容性

需要支持 IndexedDB 的现代浏览器（Chrome、Firefox、Edge、Safari 10+）。

## 4. 角色与权限

系统支持两种角色，在[个人资料页](src/pages/Profile/Profile.jsx)设置：

### 求职者（Seeker）
- 浏览机会列表
- 收藏 / 取消收藏职位
- 投递申请
- 查看和管理自己的申请记录

### Boss（招聘方）
- 浏览机会列表
- 收藏 / 取消收藏职位
- **发布新职位**（右侧 + 按钮）
- **删除职位**（鼠标悬停显示删除按钮）

## 5. 页面详细说明

### 5.1 登录页 `/`

[`Login.jsx`](src/pages/Login/Login.jsx)

### 5.3 机会列表 `/opportunities`

[`Opportunities.jsx`](src/pages/Opportunities/Opportunities.jsx)

- **Boss 专属**：右侧显示添加按钮，可发布新职位并选择图标

### 5.4 我的申请 `/applications`

[`Applications.jsx`](src/pages/Applications/Applications.jsx)

- 展示所有投递记录，每条记录包含公司、职位、状态、备注
- **新增申请**：从机会列表中选择公司和职位，支持图标选择器
- **状态变更**：切换为面试中/Offer/未通过/简历筛选等状态
- **删除申请**：删除指定申请记录
- **状态日志**：变更状态时自动记录系统日志

### 5.5 收藏夹 `/saved`

[`Saved.jsx`](src/pages/Saved/Saved.jsx)

- 展示所有收藏的职位和文章

### 5.6 收件箱 `/inbox`

### 5.7 系统记录 `/systemlog`

[`SystemLog.jsx`](src/pages/SystemLog/SystemLog.jsx)

- 时间线 UI 展示所有系统操作日志
- 每条记录显示操作类型、详情、操作人、时间（动态计算）
- 操作类型图标映射（🔐登录 / 📤投递 / ✏️改资料等）

### 5.8 个人资料 `/profile`

[`Profile.jsx`](src/pages/Profile/Profile.jsx)

- 编辑显示名称、邮箱、身份角色（求职者/Boss）

### 5.9 社区动态 `/feed`

[`feed.jsx`](src/pages/feed/feed.jsx)

- 展示社区帖子（预置示例数据）

[`App.jsx:190-234`](src/App.jsx:190)

- 顶部导航栏铃铛按钮
- 下拉显示最近 **3条未读** 消息
- 点击消息**标记为已读**并刷新列表
- 每次打开铃铛时重新从数据库读取最新数据
- 链接到收件箱查看全部

### 5.11 顶部导航按钮

[`App.jsx:190-209`](src/App.jsx:190)

### 5.12 深浅主题

- 点击月亮/太阳图标切换
- 通过 CSS 变量 `[data-theme="dark"]` 控制
- 主题偏好保存在 `localStorage` 的 `theme` key 中
- **登出不清理主题**，登录页也会读取并应用主题

## 6. SEEDED_KEY 版本号机制

### 6.1 什么是 SEEDED_KEY

[`db.js:122`](src/utils/db.js:122)

```js
const SEEDED_KEY = 'db_seeded_v4'
```

这是一个 **localStorage 标记**，用来判断是否已经填充过示例数据。

**工作流程：**

```js
export async function seedIfEmpty() {
  // 第125行：检查 localStorage 中是否有这个 key
  if (localStorage.getItem(SEEDED_KEY)) return  // 有 → 跳过，不再填充

  // ... 第132-179行：填充示例数据到 IndexedDB ...

  // 第203行：填充完成后写入标记（值固定为 '1'）
  localStorage.setItem(SEEDED_KEY, '1')
}
```

### 6.2 核心理念：一句话规则

```
需要改版本号 = 修改了 db.js 第132-179行中5个示例数据数组的内容
不需要改版本号 = 其他所有情况（修复Bug、新增页面、修改逻辑等）
```

### 6.3 详细对照

**需要改版本号 ✅** — 仅当你修改了 [`db.js:132-179`](src/utils/db.js:132) 中以下 **5 个数组的内容**时：

| 数组名 | 用途 | 修改操作示例 |
|--------|------|-------------|
| `opportunities` | 职位机会 | 新增/删除职位、改公司名/薪资/描述/标签 |
| `applications` | 申请记录 | 新增/删除申请、改状态/备注 |
| `savedItems` | 收藏项 | 新增/删除收藏、改关联的 `jobId` |
| `messages` | 系统消息 | 新增/删除消息、改发件人/内容/时间戳 |
| `systemLogs` | 操作日志 | 新增/删除日志、改操作类型/详情 |

包括：添加条目、删除条目、修改字段值、新增字段、删除字段、改变时间格式等**任何数据内容变化**。

> **目的：** 让旧用户的浏览器重新执行 seed，用新数据结构覆盖旧数据。

**不需要改版本号 ❌** — 其他所有情况：

| 修改类型 | 示例 |
|----------|------|
| 修复 UI Bug | 按钮样式、布局错乱、颜色不对 |
| 修复功能逻辑 | 收藏按钮不亮、时间不显示、通知不刷新 |
| 新增页面 | 添加设置页、帮助页 |
| 修改路由 | 调整导航顺序、更改路径 |
| 添加新功能 | 导出数据、搜索过滤 |
| 重构代码 | 拆分函数、重命名变量 |
| 修改工具函数 | `formatTime`、`logActivity`、`getAllSystemLogs` |
| 修改样式文件 | CSS 变量、主题颜色、布局 |

> **原因：** 这些修改不涉及示例数据，旧用户不需要重新 seed。新用户首次打开时无论版本号是多少都会执行 seed。

### 6.4 版本号修改步骤

```diff
// db.js 第122行
- const SEEDED_KEY = 'db_seeded_v4'
+ const SEEDED_KEY = 'db_seeded_v5'
```

同时修改示例数据（第132-179行）中的内容。

### 6.5 版本号演变历史

| 版本 | 变更原因 | Seed 数据变化 |
|------|----------|---------------|
| `v1` | 初始创建 | 全部示例数据 |
| `v2` | 收藏星标不亮 | `savedItems` 添加 `jobId` 字段 |
| `v3` | 消息时间格式错误 | `messages` 添加 `_timestamp` 字段 |
| `v4` | 所有时间硬编码 | `opportunities` 使用 `_posted` 时间戳 |

### 6.6 如何手动清空 seed 数据重新填充

**方法一：删除 localStorage 标记（推荐）**
1. 打开浏览器开发者工具（F12）
2. 进入 Application → Local Storage
3. 找到 `db_seeded_v4` 并删除
4. 刷新页面 → seed 会重新执行

**方法二：清空所有数据**
1. 打开浏览器开发者工具（F12）
2. 进入 Application → IndexedDB
3. 右键删除 `CareerCompassDB`
4. 同时也删除 Application → Local Storage 中的 `db_seeded_v4`
5. 刷新页面

### 7.2.1 STORES 配置详解 — 如何新增仓库

[`db.js:9-15`](src/utils/db.js:9)

```js
const STORES = {
  applications: { keyPath: 'id' },
  saved_items:   { keyPath: 'id' },
  messages:      { keyPath: 'id' },
  opportunities: { keyPath: 'id' },
  system_logs:   { keyPath: 'id' },
}
```

**`STORES` 是什么？**

`STORES` 是 IndexedDB **对象仓库（Object Store）配置表**，每个 key 对应一个仓库名称，value 是创建该仓库时传递给 `createObjectStore` 的选项参数。`keyPath: 'id'` 表示每条数据记录都必须有一个 `id` 字段作为主键。

**如果想新增一个仓库（例如"标签管理"），需要怎么做？**

分 **3 步**：

#### 第 1 步：在 `STORES` 中添加新仓库配置

```diff
// db.js 第9-15行
const STORES = {
  applications: { keyPath: 'id' },
  saved_items:   { keyPath: 'id' },
  messages:      { keyPath: 'id' },
  opportunities: { keyPath: 'id' },
  system_logs:   { keyPath: 'id' },
+ tags:          { keyPath: 'id' },  // 新增标签仓库
}
```

#### 第 2 步：递增 `DB_VERSION`

```diff
// db.js 第6行
- const DB_VERSION = 3
+ const DB_VERSION = 4   // 新增仓库必须升版本号
```

> **为什么必须升版本号？**
>
> IndexedDB 的模式（schema）变更只能通过 `onupgradeneeded` 事件触发。[`openDB()`](src/utils/db.js:18) 在第21行监听此事件，遍历 `STORES` 调用 `createObjectStore`。但该事件 **仅在版本号递增时才会触发**。不升版本号，新仓库不会被创建，写入数据时会报"store not found"错误。

#### 第 3 步：使用新仓库

```js
import { add, getAll } from '../utils/db'

// 写入数据
await add('tags', { id: 't1', name: '前端开发', color: 'blue' })

// 读取数据
const allTags = await getAll('tags')
```

`add`、`getAll`、`getById`、`put`、`del`、`clear` 等通用 CRUD 函数都支持任意仓库名称，无需额外修改。

> **⚠️ 注意**：如果新仓库也需要填充示例数据，记得同时参考 [6. SEEDED_KEY 版本号机制](#6-seeded_key-版本号机制) 更新 seed 逻辑。

### 7.3 localStorage 存储说明

| Key | 用途 | 登出是否清除 |
|-----|------|-------------|
| `user_profile` | **合并存储** — 邮箱 + 个人资料（名字、头像色、性别、身份、密码） | ✅ 清除 |
| `theme` | 主题偏好（light/dark） | ❌ 保留 |
| `db_seeded_v4` | 示例数据已填充标记 | ❌ 保留 |
| `remember_credentials` | 记住的邮箱密码 | ❌ 保留 |

> **注意：** `userEmail` 和 `user_profile` 已合并为一个 key [`user_profile`](src/utils/db.js:255)，内部包含 `email`、`displayName`、`avatarColor`、`gender`、`role`、`password` 等字段。登出时只需删除这一个 key 即可清除所有用户数据。

### 7.4 认证与路由守卫

**认证逻辑：**
- 登录成功 → 写入 `localStorage.setItem('user_profile', JSON.stringify({ ...existing, email }))`

- [`App.jsx`](src/App.jsx:59) — 未登录自动跳转登录页
- 登出 → `localStorage.removeItem('user_profile')` — 一个 key 清除所有用户数据

## 8. 常见问题

### Q1: 登录后直接跳转到登录页？

> 检查浏览器是否支持 IndexedDB，或在 Application → Local Storage 中确认 `userEmail` 是否存在。

### Q2: 页面一直显示"加载中..."？

> 可能是 IndexedDB 首次初始化较慢，刷新页面重试。如果持续出现，检查浏览器控制台是否有错误。

### Q3: 修改代码后示例数据没有更新？

> 见 [6.6 如何手动清空 seed 数据](#66-如何手动清空-seed-数据重新填充)。如果修改了 seed 数据结构，需要升级版本号。

### Q4: 切换主题后页面闪烁或颜色不正常？

> 系统在 `index.html` 的 `<script>` 中同步读取 `localStorage` 设置 `data-theme`，确保首帧就应用正确主题。如果还有问题，清除 `localStorage` 中的 `theme` 重新设置。

### Q5: 登出后收藏/申请数据会丢失吗？

> 不会。所有数据存储在 IndexedDB 中（浏览器本地数据库），登出仅清除 `localStorage` 中的登录信息。重新登录后数据仍在。

### Q6: 如何在另一台电脑上同步数据？

> 当前系统使用浏览器本地 IndexedDB，数据不自动同步。可以导出 IndexedDB 数据手动迁移，或后续接入后端数据库实现云端同步。
